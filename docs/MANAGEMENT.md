# 项目、定时更新与多设备管理

## 部署和目录挂载

使用本仓库构建的 DockerCopilot 镜像。生产镜像包含官方 Docker CLI、Compose 插件、CA 证书和时区数据，支持 Linux amd64、arm64。只替换旧容器的程序文件无法补齐 CLI，需要先升级完整镜像。

在 DockerCopilot 的服务配置中增加：

```yaml
environment:
  COMPOSE_ROOT: /srv/compose
  TZ: Asia/Shanghai
volumes:
  - /var/run/docker.sock:/var/run/docker.sock
  - ./data:/data
  - /srv/compose:/srv/compose:rw
```

将 `/srv/compose` 换成宿主机的实际项目目录，容器内使用相同绝对路径。Compose 解析出的 bind mount 路径由宿主机 Docker daemon 使用；两个路径不一致会使相对卷指向错误位置。项目的 `.env`、`env_file` 及相对文件路径按官方 Compose 的项目目录规则解析。每台设备挂载自己的项目目录，主容器通过远端接口访问该设备的文件。增加或调整挂载后，修改部署配置并重新创建对应 DockerCopilot 容器。

`COMPOSE_ROOT` 默认 `/compose`，必须为绝对路径；没有挂载时仍可使用容器、镜像等其他功能。节点设置、设备凭据和接管记录默认保存在 `/data`，必须持久化。`DATA_DIR` 可改变数据目录，图标配置和图片位于其中的 `config/imageLogos.js`、`config/image/`；未设置时仍沿用 `/data/config`。

旧版本的图标固定使用 `/data/config`。如果此前只为节点设置指定了其他 `DATA_DIR`，升级前需将原图标配置及图片复制到新数据目录的 `config/`，核对目标已有内容后再启用；程序不会自动迁移或删除旧目录。继续使用默认 `/data` 的部署无需调整。

常规部署保留启动、挂载及 Docker 连接参数：

| 环境变量 | 默认值或行为 | 用途 |
| --- | --- | --- |
| `secretKey` | 必须设置，至少 8 位且非纯数字 | 登录及令牌签发 |
| `TZ` | 生产镜像为 `Asia/Shanghai` | 系统时间及定时计划时区 |
| `DOCKER_HOST` | `unix:///var/run/docker.sock` | 连接 Docker daemon |
| `COMPOSE_ROOT` | `/compose` | 受管项目根目录，与宿主机同路径读写挂载 |
| `DATA_DIR` | `/data` | 持久化设置、设备、图标和接管记录 |
| `DOCKER_API_VERSION` | 自动协商 | 高级连接参数，通常无需指定 |
| `DOCKER_CERT_PATH`、`DOCKER_TLS_VERIFY` | 不加载自定义证书 | Docker TLS 证书目录及服务端验证，启用验证使用 `"1"` |
| `WORKDIR` | `/app` | 启动脚本查找程序和配置的工作目录 |

README 的 `DOCKERCOPILOT_IMAGE` 是宿主机环境或 `.env` 中的 Compose 镜像地址插值变量。网络代理、旧容器保留和 GitHub 加速统一使用下文的界面设置，不再作为常规环境变量配置。

## 接管和编辑已有 Compose 项目

1. 打开应用、刷新或重新登录后默认进入「项目」，手机底部导航也可直接进入。在导航中选择需要管理的设备。项目由官方 Docker Compose 管理。系统读取现有容器标签，并在挂载根目录及其一级子目录扫描常见主文件及 override 文件，以卡片展示项目；总项目列表优先展示运行中（含部分运行）的项目，同组保留原有顺序。点击统计栏可筛选运行中、未运行、有更新或配置异常的项目。「有更新」按项目计数，一个项目有任一容器确认可更新即计入，卡片右上角显示与容器列表相同的黄色 NEW 角标；更新完成后数量、角标和筛选结果同步刷新。
2. 尚未运行的项目也可接管。点击「接管项目」，按主文件、override 顺序每行填写一个已有文件路径，支持 `deployment.json` 等其他文件名或自定义多文件组合。项目名可以显式指定。
3. 点击项目卡片打开编辑窗口，选择配置文件，在等宽编辑区修改文本。支持 YAML、YML、JSON，单文件上限 2 MiB。文件注释、文本格式、原有 LF/CRLF 换行风格及末尾换行会保留。可点击「重新加载文件」读取宿主机的最新内容；关闭窗口或切换文件前会确认未保存的修改。
4. 读取文件及停止输入约 650ms 后自动检查当前草稿；状态显示在「配置文件」右侧，中文错误显示在编辑框下方，可点击行号定位语法问题。检查使用官方 `docker compose config --quiet`，将当前草稿通过 stdin 替换有序文件组合中的对应文件，不写入磁盘、不部署、不创建任务。继续编辑、切换文件或设备会取消前端旧请求并忽略已失效的结果，过期结果不会覆盖当前内容。
5. 「保存」先检查语法，成功后显示「已保存，尚未部署」；语法错误时禁止保存，完整项目配置有误时仍可保存语法正确的中间文件，修正后再部署。「保存并部署」保存后提交部署任务，部署前始终再次检查完整配置。检查不可用时显示原因，不能视为配置通过。
6. 编辑窗口的服务选择采用紧凑卡片，点击服务名或使用空格多选；未选择时操作整个项目。底部保留「启动／停止」「更新」「更多」；启停随所选服务的运行状态切换，混合运行时可在「更多」启动未运行的服务，「重启、拉取镜像、部署」也收进该菜单。项目卡片上的操作始终作用于整个项目。提交后沿用容器卡片的展示方式，在原卡片显示当前步骤与百分比，不再弹出进度窗口；编辑窗口也同步显示。不同项目可同时显示各自进度，所属容器页同步显示项目任务；关闭编辑窗口、切换页面或刷新浏览器不取消任务，返回后可继续查看；完成后恢复操作按钮，成功提示展示约 3 秒后恢复项目当前状态，失败或恢复原因统一在卡片底部显示一次，完整记录可在「执行记录」查看。进度读取失败时只刷新结果，不重复提交操作。
7. 项目卡片的「容器」按钮跳转到该项目的容器列表；编辑窗口中服务卡片右侧的容器图标可查看该服务的容器。容器卡片及详情中的「更新」可直接确认并更新该容器所属的项目服务，无需先进入项目编辑窗口；同一服务的全部副本会一并更新，应用该服务已保存的配置，其他服务不在本次更新范围内。容器卡片左上角的项目标签仅展示归属，不单独占用一行；底部「项目」按钮可返回对应项目并选中服务，修改镜像也通过项目编辑器进行。「清除筛选」恢复全部容器；统计及批量全选以当前项目、服务和状态筛选为准，切换设备后清除定位条件。

手机界面支持添加到主屏幕后以 PWA 独立窗口使用；安装和 Service Worker 需要浏览器的安全上下文（HTTPS 或本机 localhost）。顶部、底部导航及弹窗避开设备安全区，软键盘弹出时弹窗跟随可视高度滚动、底部导航暂时收起，键盘关闭后恢复。离线缓存只保存页面和静态资源，容器、项目及设备接口始终访问网络。

保存时会比较打开文件时的原文与当前磁盘内容。其他页面或宿主机修改过文件时，本次保存被拒绝，应重新加载后合并。保存使用同目录临时文件和原子替换，保留权限及 Linux 所属用户、组；只读挂载、只读文件、目录穿越、符号链接、特殊文件均被拒绝。编辑限于挂载根目录内已接管项目的配置文件，不提供任意宿主机文件编辑或网页创建项目功能。

不同目录中的项目需使用唯一项目名：Compose 按项目名识别容器，目录不同无法隔离同名项目。检测到重名时会提示重新接管。自动扫描最多 20,000 个条目，仅检查 `COMPOSE_ROOT` 本身及其一级子目录，不继续扫描项目内部的备份、数据或其他深层目录。更深的项目仍可通过现有容器标签识别（包含已停止的容器），没有容器的深层项目可按已有文件路径显式接管。调整发现范围不会删除项目文件、备份或容器。

服务操作支持启停、重启、拉取、部署及拉取后更新。未选择服务时操作整个项目，选择后只操作对应服务。完整配置校验失败时不会修改运行中的容器。草稿检查的语法、字段类型、未知字段、依赖、端口及环境文件等常见错误转换为中文；只返回结构信息，无法识别的错误提供中文排查建议。原始 Compose 输出可能含环境值，不直接返回或写入日志；任务保留退出状态和可提取的行号，需要完整排障信息时，在该设备宿主机对相同项目运行 `docker compose config`。

**已保存但未部署的配置会在后续自动更新命中该服务时应用。** 如果暂时不希望应用修改，请先将该服务加入排除规则。

## 检测、自动更新和代理

桌面页头操作按钮与标题同行，保留图标与文字；容器页的「批量操作」从标题右侧展开六宫格菜单。手机的项目、镜像和容器批量操作与下文的底部导航合为同一组件，页头不再显示这些操作按钮；容器列表沿用每 10 秒自动刷新。项目根目录与标题同行展示，长路径省略、悬停可查看完整路径，不再单独占用列表上方一行。容器两端共用全选、启动、停止、重启、更新及退出操作，选择遵循当前筛选范围。收起菜单保留所选容器，「退出」清除选择并结束批量模式；切换设备或离开容器页清除批量状态。

手机底部采用 LeiBox Glass Tab Menu：项目、容器、镜像页的四项导航旁提供加号，点击后同一个玻璃表面固定底边、向上展开，加号旋转为关闭图标。项目页显示「接管项目、刷新」两项，镜像页显示「无Tag、未使用、刷新」三项，均按单行排列；镜像清理仍先确认候选范围，无可清理镜像或正在加载时禁用对应操作。容器页展开六宫格批量菜单。关闭图标、空白处或 Esc 收起菜单并恢复导航，容器入口角标继续显示已选数量，便于在列表中继续点选。切换页面或设备时收起菜单，操作绑定当前页面及设备。展开不改变页头和列表位置，底部始终保留 64px 占位。面板、圆钮、选中块及操作按钮沿用组件源码的玻璃渐变、白色高光边框、内阴影与模糊参数；操作按钮以文字颜色区分状态，不使用实色填充覆盖玻璃材质。内容滚过底部时透出背景；系统减少透明度或提高对比度时使用实色底板。

导航选中块只跟随已确认的页面切换；待保存、确认离开或取消离开期间仍指向当前页面。页面操作入口出现或隐藏后按最终导航宽度重新定位，避免选中块偏移。方向键、Home 和 End 可移动焦点，回车激活入口；系统启用减少动态效果时直接切换选中位置及展开状态。软键盘隐藏导航、切换到桌面布局或卸载组件时停止动画，恢复后按实际按钮位置重新测量。浅色、深色和安全区均沿用项目设置。

桌面侧栏和手机底部导航统一提供「项目」「容器」「镜像」「设置」。手机不再提供侧栏，顶部直接显示可点击的当前设备和下拉箭头，右上角依次提供外观、更多和退出登录；点击外观图标直接按「浅色 → 深色 → 跟随系统 → 浅色」循环切换，不弹出面板，图标及提示显示当前外观，选择在刷新后保留。「更多」提供当前设备版本、项目源码和问题反馈。底部四项导航保持常驻，软键盘打开时隐藏。进入「设置」后，可在「更新设置」「消息推送」「设备管理」「图标库」四个分类间切换；手机使用「通知」短标签。本次登录期间再次进入设置会回到上次分类，切换设备也保留当前分类。桌面「项目源码」「问题反馈」仍以带图标的黑底、浅蓝底按钮放在侧栏底部版本信息下方，侧栏收起时纵向排列并保留文字。

进入「设置 → 更新设置」配置当前设备，当前管理设备由导航区的设备切换入口统一显示。「定时计划」只设置一个执行频率，支持常用频率和自定义五段 Cron，并显示设备时区与下次执行时间。「发现更新后自动更新」关闭时只检测并刷新更新提示；开启后，按相同频率检测，并使用本次结果更新符合条件的容器和项目服务。「启动时仅检测」独立控制启动检测，启动时不会自动更新容器。

| 项目 | 默认值 |
| --- | --- |
| 启动时检测 | 开启 |
| 执行频率 | `30 * * * *`，每小时第 30 分钟 |
| 发现更新后自动更新 | 关闭 |

旧配置已开启自动更新时，统一计划沿用原自动更新频率；未开启时沿用原检测频率，页面会简短提示来源。合并后不再分别执行两种频率，例如原「每小时检测、每天 03:00 自动更新」将变为「每天 03:00 检测并更新」。切换自动更新开关不改变当前频率及下次执行时间，实际触发时读取最新开关。兼容读取原 `checkCron`、`updateCron` 字段，仅修改频率或自动更新模式时将两者统一；保存代理、通知等其他字段保留旧 Cron。旧版远端没有统一调度能力时仍显示双计划，升级该设备后使用统一计划。

「更新设置」和「消息推送」修改后自动保存，无需点击保存按钮。开关、常用频率和排除项修改后立即提交；文本停止输入 500 毫秒后提交，失焦或回车时立即提交，输入法组字期间不提交。保存状态以紧凑标签显示在页头标题右侧，手机端也保持同行。校验错误在对应的 Cron、代理、Bark 地址或密钥框下显示，网络、服务及无法定位的错误集中提示，原因与「重试」操作放在一起；失败保留输入，后台继续使用上次成功保存的配置。切换分类、页面、设备或退出登录前会等待待保存内容完成，仅在仍有失败或无效输入时提示是否放弃修改。

设置按实际修改字段局部提交，设备在设置锁内合并并原子保存，不同分类同时保存不会覆盖彼此的设置。连续修改串行提交并保留最新输入，某个无效输入不阻止其他独立设置保存。未修改值时不重复写文件；只有生效的 Cron 变化时才重建唯一计划。所有设置保存均保留上次镜像检测结果，不自动启动检测。代理修改后，后续检测请求使用新代理，可点击「立即检测」验证；自动更新每轮重新检测，不以列表历史结果决定更新。「启动时仅检测」控制后续启动行为，修改本身不会执行检测。

计划和代理持久化在当前设备，重新启动后恢复。执行时间使用该设备的 `TZ`。不同项目及独立容器可并行操作，同一项目的服务和所属容器共用锁；容器改名、替换以及更新失败恢复期间仍受保护。配置保存与所属项目变更互斥，共用文件的保存串行执行。冲突请求返回 HTTP 409，不排队叠加。镜像删除、清理及 DockerCopilot 自身升级需要节点独占，正在执行对象变更时拒绝，程序即将重启时也不接受新变更。启动检测、定时计划和手动检测／批量更新共用设备内的任务互斥，不重叠运行；检测不阻塞对象操作，更新时逐个锁定对象，忙碌对象记录跳过原因并继续处理其他对象。检测和更新任务在设备本地运行，主容器离线不影响受管设备的计划。

「立即检测」「检测并更新」位于定时计划卡片标题栏右侧，不单独占用底部一行；沿用项目卡片的白底描边与操作颜色。桌面显示图标和文字，手机显示带名称及提示的图标按钮。下次执行以紧凑摘要与频率选择框对齐，突出时间，标签和设备时区弱化显示，窄屏自然换行。两者在启动前先等待自动保存完成，确保使用最新保存的代理及排除项；存在保存失败或无效输入时提示并停止启动。后者不依赖定时自动更新开关，但需确认后才执行。「下次执行」始终显示已保存计划的时间；保存成功但回读失败会单独提示刷新异常，不误报为保存失败。提交后弹窗显示执行结果，离开页面不取消任务；收起后可从标题栏的进度按钮重新打开。页面顶部「执行记录」可查看当前设备的检测、更新和 Compose 操作，一次检测并更新保留一条记录，详情包括检测、更新、跳过及失败原因。

每次任务先检测，再根据本次结果执行更新；相同镜像引用、本地镜像和平台在本次任务内复用结果，失败结果也不会重复请求。不同任务重新检测，不以列表历史提示直接决定更新。更新前继续取得对象锁并复核镜像、名称和运行状态；检测后已变化或无法确认的对象跳过。Compose 按已保存配置中的目标镜像检测，目标不同于当前容器镜像时单独检测，不把目标结果写成当前镜像的列表提示。某项检测或更新失败不阻止其他符合条件的对象。

在「自动更新排除项」的单一「排除容器」下拉框中搜索并多选，统一列出独立容器和项目容器，选中项以标签显示，可移除或清空，修改后立即自动保存并生效。只显示选中数量，不再分别设置项目服务或显示关联计数。项目按服务排除：选择任一副本会选中该服务的所有副本，取消任一副本会取消该服务及其已知副本的排除，不影响同项目中的其他服务。

新选择的独立容器按名称保存，项目容器在内部按所属服务保存，避免容器重建或副本增减后排除失效。兼容已有的容器 ID、名称及项目服务规则，读取或保存其他设置时不自动转换；暂不在列表中的容器规则和暂无对应容器的服务规则仍显示在同一入口中，可查看和移除。取消一个项目容器时，同时移除该服务及其已知副本的旧 ID、名称规则，避免残留排除；清空选择会移除全部排除规则，包括离线规则。项目服务信息不可用时保留已有规则，暂不允许新增归属无法确认的项目容器排除。

排除影响定时自动更新和「检测并更新」，不限制容器或项目中的直接手动更新。任何副本被排除或停止时，整个服务跳过，其他服务仍按自己的规则处理；同一服务的多个副本不能分别自动更新。自动更新默认跳过停止的容器、DockerCopilot 自身、自动删除容器、依赖旧式 links/volumes-from 或其他容器命名空间的对象，任务详情会说明。

已停止容器仍参与元数据检测并显示更新提示，但不会被自动更新或启动。只有配置文件、没有容器的项目没有已部署镜像作为比较对象，暂不检测或自动部署。部分运行的项目可以自动更新其中符合条件的运行服务；一个服务有任何停止副本时整个服务跳过。手动更新独立容器需先启动；手动更新或部署项目可能启动所选范围的停止服务，确认窗口会明确提示。

「网络设置」统一放置「代理地址」和「GitHub 加速地址」，桌面标签与输入框对齐，手机端上下排列。代理地址支持 HTTP、HTTPS、SOCKS5 及 SOCKS5H，清空表示直连；编辑后统一用于 HTTP 和 HTTPS 请求。停止输入 500 毫秒后自动保存，失焦或回车时立即提交，保存后刷新版本查询，无需重启，不自动执行镜像检测。

兼容已有的分开配置：两项不同时优先显示非空 HTTPS 代理，否则显示 HTTP 代理，并提示修改后统一；未编辑代理时，保存其他设置不会改写原配置。代理可包含认证信息，接口仅对密码返回掩码，界面不回传未改动的凭据；编辑带认证的代理地址后需重新填写完整密码，避免将掩码保存成密码。编辑期间保留完整输入，失焦且最新值保存成功后再显示掩码，不因回读设置而打断输入。

代理用于镜像仓库认证、令牌和 manifest 请求，以及未配置 GitHub 加速地址时的版本查询和程序下载。镜像检测只读取元数据，不拉镜像层；会匹配仓库端口、标签、当前架构及默认平台变体，比较平台镜像的 config digest。固定 digest 的引用不会提示标签更新。TLS 正常验证，证书、认证、超时或平台匹配失败时显示「无法确认」，自动更新跳过。需要私有仓库凭据但无法取得公开令牌时，也会显示无法确认。

**Docker daemon 拉取镜像的代理由宿主机配置。** 本次没有新增私有仓库凭据管理，代理设置不能代替仓库登录。

「独立容器更新」中的「保留更新前的旧容器」默认关闭，适用于独立容器的手动、批量和自动更新。每个容器开始更新时读取一次已保存策略，途中修改只影响后续更新；旧接口的单次保留请求仍可使用，但不能强制覆盖设备的保留设置。此项不控制 Compose 服务的旧容器保留，也不替代更新失败恢复。

「GitHub 加速地址」是 URL 前缀，实际访问地址为 `前缀/原始GitHub地址`，支持 HTTP/HTTPS 及路径前缀，不接受查询参数和片段。**设置加速地址时直连加速服务，不走代理；未设置时使用代理地址访问 GitHub；两项均为空时直连 GitHub。** 一次程序更新的版本查询与下载使用开始时同一份网络设置。版本缓存五分钟，仅相同的有效网络设置可命中，修改加速地址或实际使用的代理后重新查询。认证密码沿用代理的脱敏规则。开发版仍通过升级完整容器镜像更新，修改此处不会为 Docker daemon 配置镜像拉取代理。旧版设备缺少设置字段时显示升级提示并禁用对应控件。

**旧环境变量仅迁移一次：** 启动时，只有 `httpProxy`、`httpsProxy`、`keepOldContainer`、`githubProxy` 中缺失的字段才从旧 `HTTP_PROXY`、`HTTPS_PROXY`、`DelOldContainer`、`githubProxy` 初始化；已有空值或 `false` 不被覆盖。旧 `DelOldContainer` 只有精确值 `"false"` 会迁移为开启保留。迁移同时持久化默认值，后续修改环境变量不再影响配置。迁移成功并核对界面值后可删除这四个旧环境变量；迁移校验或写入失败会报告原因并保留原设置文件。

## 消息推送

在「设置 → 消息推送」配置当前设备的 Bark。总开关默认关闭，「发现镜像更新、检查异常、更新成功、更新失败」四项默认勾选。服务器默认 `https://api.day.app`，支持 HTTP/HTTPS 自建服务及路径前缀；设备密钥只写入，读取仅返回已配置状态，编辑时留空保留原密钥。

通知设置同样自动保存。首次开启缺少密钥时会保留输入，在 Bark 密钥框下提示原因，补齐有效连接配置后自动重提启用修改。密钥在输入期间保留，失焦且最新值保存成功后清空，只显示已配置状态。测试推送的结果就近显示在 Bark 卡片内。

「测试推送」位于 Bark 卡片标题右侧，使用当前填写的服务器和密钥，密钥留空时使用已保存值；测试本身不保存设置、不切换总开关、不创建容器任务，也不受总开关限制，正常自动保存仍按上述时机进行。「Bark 已接受推送」表示服务端接受请求，手机实际收到仍取决于 Bark App、设备注册及系统通知权限。旧版设备会显示升级提示并禁用设置和测试。

通知来源为 DockerCopilot 的检测、检测并更新、独立容器更新及项目服务更新任务。每个现有 taskID 结束后最多发送一条汇总；多个独立手动任务各自汇总。标题直接显示结果与数量，例如「DockerCopilot · 发现镜像更新 2 项」或「DockerCopilot · 成功 1 · 失败 2 · 检查异常 1」。正文首行仅保留设备与月日、时分，其后列出对象和镜像引用；单类结果不重复标注状态，混合结果逐项标注，失败保留「已恢复」或「恢复失败，需处理」。Compose 服务合并副本数量，如「media/web（3 副本）」。正文优先列异常，按 UTF-8 安全截断至 2KB，省略时标注「另有 N 项，详见执行记录」。设备使用 Docker 主机名，读取失败时回退本机主机名；不推断镜像内应用的版本号，不发送原始 Compose、环境变量或设备密钥。

全部最新且没有异常时静默；每轮仍发现更新时再次提醒。检测并更新任务在全部对象处理后统一发送，成功对象不再列为待更新；失败、已恢复、恢复失败分别保留。只发送已勾选的内容，没有匹配内容时静默。

Bark 请求由任务所在设备直连，不使用网络代理，正常校验 TLS，不跟随重定向，整体最长 10 秒且不自动重试。对象操作锁释放、任务结果确定后才发送；发送失败只影响任务独立的通知状态，不改变容器任务结果。执行记录可查看「Bark 已接受推送」或中文失败原因，设备本地通知不依赖主端或浏览器在线。

## 更新验证与失败恢复

普通容器先读取实际运行配置，再拉取镜像，拉取过程中旧容器继续运行。替换后，有健康检查则最长等待 120 秒；无健康检查则观察连续运行 10 秒，出现退出或新重启视为失败。验证成功后默认删除旧容器；在「设置 → 更新设置」开启「保留更新前的旧容器」时，旧容器停止并改名保留，释放网络端点以避免静态 IP 冲突。

Compose 自动更新以服务为单位，只更新确认有新镜像的现有运行服务，保留当前副本数。使用 `--no-build`、`--no-deps`、健康等待及拉取后 `--pull never`，不构建镜像、不删除卷、不清理其他服务。更新会应用所选服务在当前文件中的配置。

更新成功仅使本次涉及容器的检测结果失效，其他对象的更新提示保留；检测期间对象被替换或改名时，过期结果不回写。

通过健康验证并完成旧容器、临时恢复标签清理后，自动尝试删除本次更新留下的无标签旧镜像。仅检查本次旧镜像 ID，不全局清理，不强制删除，不递归删除父镜像。运行中或已停止容器仍引用的镜像、带有其他标签的镜像均保留；保留旧容器时其镜像也会保留。其他对象正在变更时跳过这次镜像清理，避免干扰它们；清理失败或跳过单独写入任务结果，不把已验证成功的更新改成失败，可稍后在镜像页处理。更新失败或恢复失败时不清理其旧镜像。

更新前记录实际容器配置、旧镜像 ID、真实卷和网络。Compose 在 `/data/recovery` 保存临时恢复资料并给旧镜像增加临时标签；正常完成或恢复成功后清理，恢复失败时保留。恢复使用运行快照，不使用已经编辑过的 Compose 文件。普通容器优先恢复原来的旧容器。

恢复只覆盖容器配置和镜像，**不回退卷内数据、数据库迁移或外部系统变更**，这些由宿主机备份处理。任务分别显示成功、失败、失败且已恢复、恢复失败；恢复失败时应查看任务详情并人工处理。此机制不提供断电后的自动恢复队列：进程异常退出时已保存的配置和容器仍在，需检查设备实际状态。完成任务最多保留 200 条，任务历史在内存中，设备重启后重新记录，丢失的任务不会被标记为成功。

手动备份、Compose 导出及从备份恢复功能已移除，旧备份接口不再提供或转发，`BACKUP_DIR` 不再使用。已有备份文件不会自动删除，可由宿主机自行保管。此调整不影响更新过程中的失败恢复。

## 多设备统一接管

1. 在每台设备安装同一功能版本的 DockerCopilot，分别设置登录密钥、持久化数据目录和 Compose 目录挂载。
2. 在主容器进入「设置 → 设备管理」，填写名称、`http(s)://主机:端口` 和远端登录密钥。使用可信内网或 HTTPS 地址。该分类标注「主端接入列表」，不随当前所选设备改变管理范围。
3. 保存时检查连接、版本和能力；缺少功能会提示升级远端镜像。可编辑、测试连接及移除。暂时无法连接的设备仍会保存，修正连接后再测试。
4. 点击桌面侧栏中的设备卡片、收起侧栏的显示器图标，或手机顶部带下拉箭头的设备名称，打开设备列表。手机使用底部面板，桌面使用锚定入口的弹层；本机置顶并标注「当前登录服务」，其他设备显示名称和地址，勾选表示当前管理对象，不表示设备在线。选择另一设备后保留当前页面与设置分类，清除原设备的项目、服务定位条件；设置修改先等待自动保存，仍有失败或无效输入时才确认放弃，项目文件沿用未保存确认。取消切换保留原设备与输入。容器、镜像、图标上传和预览、Compose 文件和部署、定时计划、代理、版本与程序更新都属于所选设备；列表底部「管理设备」进入主容器的接入列表，不改变当前设备。

设备列表失败时可重试，已有列表保留；当前设备被移除时显示「设备不可用」，由用户选择其他设备，不自动切回本机。设备较多时列表独立滚动，标题和「管理设备」入口固定。点击遮罩、关闭按钮或按 Esc 可关闭面板，焦点返回入口；手机适配安全区与可视区域，系统启用减少动态效果时取消面板进退场动画。

远端登录密钥保存在主容器服务端的 `devices.json`，文件权限为 0600，不返回浏览器。远端 JWT 由服务端获取及刷新；转发移除设备选择头和浏览器认证信息，防止递归转发。远端认证失败显示设备连接问题，保留主容器登录。网络超时后不自动重试结果不明的变更，请到原设备任务列表核对。

前端查询缓存、图标缓存和任务 API 均绑定设备，切换后新页面使用新设备；已经提交的任务仍在原设备执行，可回到原设备的「设置 → 更新设置 → 执行记录」查看。项目编辑器保留未保存内容的离开确认；自动更新和消息推送设置在切换分类、设备、离开页面或退出登录前先等待自动保存，仅在仍有失败或无效输入时提示是否放弃。刷新和关闭页面时，未完成修改使用浏览器的离开提示。取消离开会保留输入，保存失败也不会清除草稿。

「设置 → 图标库」提供上传、搜索、分类、收藏和预览；内置图标通用，自定义图标及收藏属于设备切换入口中选中的设备。移除设备只删除主容器连接记录，不会停止远端容器或定时任务。程序版本与自身升级继续使用导航区原有入口。

## 图标管理与公开链接

在图标库顶栏点击「上传图标」，填写镜像仓库并选择 PNG、JPEG、WebP 或 GIF，单文件最大 2 MiB。SVG 需先转换为支持的格式。网格提供收藏和复制，打开详情可查看原图、替换或删除自定义图标；容器详情点击图标上传，右侧还原按钮可恢复默认图标。删除确认会列出当前设备、完整镜像仓库及全部标签的影响范围。

自定义图标优先于内置图标，按完整仓库匹配并应用到全部标签。例如为 `redis:7` 上传后，`redis:8` 和摘要引用也使用该图标；`other/redis` 的自定义图标独立。仓库端口不会被当成标签。删除后恢复内置图标，没有内置时显示默认占位。容器列表、容器详情和镜像页使用同一规则；内置只保留明确的完整名称及简单名称别名，不再任意匹配子串或前缀。

收藏按来源区分，同名内置和自定义图标可分别收藏、分别计数。旧收藏等待设备图标列表读取成功后迁移，保留原来匹配的项目。分类中的「收藏」显示数量，清空后可直接返回全部。顶栏可刷新列表，刷新失败会保留已有图标并提供重试；单张图片读取失败可在详情重试。

**图片公开只读，管理操作要求登录。** 默认复制完整图片 URL，可直接用于导航面板等其他应用；自定义图标详情也提供「复制数据链接」。剪贴板不可用或权限被拒绝时显示手动复制窗口。内置图标复制应用静态资源的完整 URL。

- `GET /icons/local/:file` 公开读取本机图片；`GET /icons/:deviceID/:file` 经主端读取远端图片，链接不含登录令牌或设备密钥。外部应用需要能够访问主端地址，远端链接也依赖主端及该设备的连接记录。
- 旧的 `/src/config/image/:file` 本机直链继续可用，配置中该路径也继续作为内部文件标识。公开入口只接受真实的 PNG、JPEG、WebP、GIF 普通文件，不提供目录列表、符号链接或任意 API 转发。
- 上传、替换、删除会生成新文件名，旧链接可能随无引用图片回收而失效；需要固定内容时可复制数据链接。移除设备后，该设备经主端提供的链接不再可用。

应用内的自定义图片接近可见区域时才通过认证接口读取，同设备同文件的网格、详情、预览及数据链接复制共享 Blob；不同设备隔离。UUID 图片按不可变内容缓存，没有组件使用五分钟后回收；组件卸载释放自身对象 URL，退出登录清除图片查询缓存。

配置读取失败会报告错误并保留原文件。写入使用进程内互斥和同目录临时文件原子替换，保存失败保留旧映射并清理未生效的新图片。替换或删除只回收本次涉及且已无映射引用的程序生成图片，手工图片、符号链接和历史孤立文件保留；回收失败会给出警告，不撤销已成功保存的配置。

历史带标签配置继续兼容：仓库级映射优先；没有仓库级映射且所有标签使用同一图片时跨标签复用；有多张不同图片时保留精确标签对应，其他标签使用内置或默认图标。首次替换或删除会归并该仓库的旧键。单个节点进程负责同一数据目录，不支持多个进程同时修改同一份配置。

程序检查与自更新使用 [本仓库正式 Release](https://github.com/thelinyue/dockerCopilot/releases)，仅接收匹配架构的正式资源，核对版本、Linux ELF 架构和包内容，不向旧版本降级；开发版通过重新构建容器更新。本仓库没有合适的正式 Release 时，界面会显示查询失败或暂无更新，不回退上游更新源。

## 镜像清理

「镜像」页的「无Tag」「未使用」清理调用 Docker 官方镜像清理接口。后者清理当前设备所有未被容器引用的镜像，支持同一镜像具有多个标签；运行中和已停止容器所用的镜像均保留。确认列表是打开时的预览，实际范围由引擎执行时的引用关系决定。

完成提示使用引擎返回的实际释放空间，不将标签或层记录计为镜像数量。出错或超时后也会刷新列表，以显示可能已经完成的部分清理；结果不明时不自动重试。单个镜像的普通删除与显式强制删除保留原有语义。

业务 API 禁用 HTTP 和 Service Worker 缓存，避免清理后刷新或设备切换仍显示旧数据。旧版应用缓存会在新 Service Worker 激活时移除，其他应用的缓存保留；离线业务请求返回连接失败，不使用页面 HTML 充当接口数据。

## 新接口

以下业务接口都需要本机 JWT。可在已认证请求中传入 `X-DockerCopilot-Device-ID: <设备 ID>` 选择受管设备；省略或 `local` 表示本机。只允许转发已注册的业务路由，设备列表接口始终在主容器执行。

| 接口 | 用途 |
| --- | --- |
| `GET /api/node/info` | 版本、Compose 目录与能力 |
| `GET /api/settings` / `PUT /api/settings` | 节点设置和下次计划；PUT 原子合并局部字段，频率或模式修改时归一兼容 Cron；`notifications` 含总开关、四类内容开关及 `bark.serverURL`，`bark.deviceKey` 只写，读取返回 `bark.hasKey` |
| `POST /api/notifications/test` | 提交 `serverURL`、`deviceKey` 测试当前设备的 Bark；密钥留空使用已存值，不保存设置 |
| `GET /api/tasks` / `GET /api/progress/:taskid` | 任务列表及指定任务进度 |
| `POST /api/checks` / `POST /api/auto-update` | 立即检测 / 检测并按已保存规则更新 |
| `POST /api/image/prune` | 按 `type: dangling / unused` 清理当前设备镜像，返回实际释放空间与是否发生清理 |
| `GET /api/compose/projects` / `POST /api/compose/projects` | 发现项目 / 按 `name`、有序 `files` 接管 |
| `GET /api/compose/projects/:id/files/:index` | 读取原文，index 从 0 开始 |
| `PUT /api/compose/projects/:id/files/:index` | 提交 `original` 与 `content` 保存 |
| `POST /api/compose/projects/:id/files/:index/validate` | 提交 `content` 检查草稿，不落盘；返回 `valid`、`syntaxValid`、中文 `message` 和可用 `line` |
| `POST /api/compose/projects/:id/actions` | 提交 `action`、`services`，返回 taskID |
| `GET /api/icons` | 当前设备的自定义图标映射，空列表为对象 `{}` |
| `POST /api/icons` | multipart `file`、`imageName`，按仓库上传或替换，返回新文件名 |
| `DELETE /api/icons?imageName=...` | 删除指定仓库全部标签的自定义映射 |
| `GET /api/icon-file?name=...` | 认证后读取当前设备图标 |
| `GET/POST /api/devices` | 设备列表 / 添加，secret 仅写入 |
| `PUT/DELETE /api/devices/:id` | 编辑 / 移除，编辑时 secret 留空保留 |
| `POST /api/devices/:id/test` | 测试版本与完整能力 |

Compose action 为 `validate`、`start`、`stop`、`restart`、`pull`、`deploy`、`update`。异步请求返回 taskID 后，需查询最终 `isDone` 和 `status`；`rolled_back` 仍表示本次更新失败，只是旧配置已恢复。

任务与进度响应可包含 `resource: { type, id, name }` 和 `action`，用于按设备和对象同步两页进度；自动更新只在占用对象期间填写 `resource`。`cleanup` 单独记录本次旧镜像清理结果，不改变任务成功或恢复状态。可选 `notification: { status, message }` 独立记录通知的 `sending`、`sent`、`failed` 状态及中文原因；通知完成后仍保留原业务 `status`。节点能力中的 `notifications` 标识消息推送支持。

设置响应的 `nextRuns.schedule` 表示统一计划的下次执行时间；`check`、`update` 保留兼容，开启自动更新时两者相同，关闭时 `update` 为零时间。旧版节点没有 `schedule` 字段，前端据此保留双计划编辑方式。`settings.keepOldContainer` 默认 `false`，控制独立容器更新成功后的保留；`settings.githubProxy` 默认空字符串，控制 GitHub 加速前缀，读取时密码脱敏。缺少新字段的远端不能通过界面修改对应选项。
